# Codex — React + Vite + Feature-Sliced Design (FSD)

## Цель

Рабочий, адаптивный MVP для хакатона без нарушения существующей FSD-архитектуры.

## Перед изменениями

- Изучи `package.json`, `src/`, алиасы импортов и существующие соглашения проекта.
- Сохраняй текущие TypeScript, роутер, стили, менеджер пакетов и подход к API.
- Не устанавливай пакеты и не проводи массовый рефакторинг без необходимости и подтверждения пользователя.

## Структура FSD

Используй уже существующие слои, по мере необходимости:

```text
  src/
  app/       # инициализация, провайдеры, глобальная маршрутизация и стили
  pages/     # композиция страниц и маршрутов
  widgets/   # крупные самостоятельные блоки интерфейса
  features/  # пользовательские действия и сценарии
  entities/  # бизнес-сущности и их представления
  shared/    # переиспользуемые UI, API-клиент, utils, config
```

- Нельзя импортировать из вышестоящего слоя в нижестоящий. Направление зависимостей: `app → pages → widgets → features → entities → shared`.
- Между разными слайсами одного слоя прямые импорты по умолчанию запрещены. Если связь нужна, перенеси общую часть ниже или пересмотри композицию; исключения применяй только по существующим правилам проекта.
- Используй публичный API слайса (`index.ts` / `index.js`), не импортируй чужие внутренние файлы напрямую.
- Внутри слайса можно использовать сегменты `ui/`, `model/`, `api/`, `lib/`, `config/`; создавай лишь нужные.
- В `shared/` и `app/` не навязывай разбиение на слайсы.
- Не создавай новые слои или абстракции только ради формального соответствия FSD.

## Куда класть код

- Новая страница → `pages/<page>/`.
- Действие пользователя (поиск, отправка формы, вход) → `features/<action>/`.
- Предметная сущность (пользователь, задача, заказ) → `entities/<entity>/`.
- Крупная композиция UI → `widgets/<widget>/`.
- Общие кнопки, поля, утилиты и API-клиент → `shared/`.
- Провайдеры, точка входа, роутинг → `app/`.
- Если код относится лишь к одному слайсу, оставь его внутри слайса; не переноси преждевременно в `shared/`.

## React + Vite

- Функциональные компоненты и хуки; соблюдай правила хуков и очищай эффекты.
- Храни состояние поближе к использованию; бизнес-логику отделяй от презентационных компонентов, если это упрощает поддержку.
- Придерживайся текущего подхода к CSS, неймингу, API-запросам и настройкам абсолютных импортов.
- Клиентские публичные настройки — `import.meta.env.VITE_*`; не размещай секреты в них.
- Для запросов обрабатывай loading/error/empty/success. Если API ещё не готово, делай легко заменяемые mock-данные внутри подходящего `api/` или `shared/` по смыслу.
- Интерфейс должен быть адаптивным и доступным с клавиатуры.

## Правила хакатона

- Сначала сделай работающий end-to-end путь, потом полируй UX.
- Предпочитай маленькие локальные изменения и ясные компоненты.
- После каждого значимого изменения запускай доступные `lint`, `test`, `build` из `package.json`.
- Перед ответом кратко укажи: изменённые слайсы, проверку сборки и оставшиеся TODO.
